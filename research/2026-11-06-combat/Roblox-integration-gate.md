# Следующий блок: RunLifecycle → реальные персонажи и физика

Статус: проект контракта для дальнейшей реализации, **не реализовано и не испытано в Roblox**. База сверки: PR №1, head `1058c9bb3daf37b889b30f24e6a622c8a274275d`, `src/server/RunLifecycle.lua`. Текущий пакет PR и ветки не меняет.

## Граница доверия

Клиент передаёт намерение атаковать и идентификаторы своего актуального состояния. Он не назначает жертву, повреждение, безопасную точку, остаток жизней или факт завершения уровня. Сервер проверяет игрока, текущий run/actor/attempt/level/connection, доступность действия, ограничение частоты и пространственные условия, затем создаёт события ядра. Это проектное требование, согласованное с официальной рекомендацией Roblox проверять любые клиентские данные на сервере [R1].

События `SetHealth`, `Death`, `CommitSpawn.safe`, `RelocateToSafety.safe` и `AdvanceLevel.destinationSafe/prerequisitesMet` из чистого ядра нельзя напрямую превратить в клиентские команды. В текущем ядре они предполагают уже принятую сервером проверку. `Death` не следует вызывать просто по client-side Touched или исчезновению из камеры.

## Последовательность одного попадания

Сервер выбирает подтверждённое действие и профиль цели-героя; проверяет защиту и контакт; вычисляет переход исходного боевого состояния; отдельно формирует реакцию/смещение; проверяет опору и тип опасности. Уменьшение здоровья, начало смертельного состояния и возврат — разные события. Для малого удара доказано, почему нельзя немедленно объявлять постоянное уменьшение здоровья по разности 47−43.

До продуктового боя требуется определить хранение исходного Life, промежуточной реакции и отображения в пяти сердцах. `SetHealth` поддерживает диапазон 0..5, но не хранит сам исходный Life и профиль. Значение 0 и решение о смерти нельзя автоматически отождествлять без проверенного отображения. Числовая формула и архитектура этого адаптера данным документом не утверждаются.

Координаты NES используют X/Y как плоскость и Z как высоту. В Roblox направление вверх использует Y; явное преобразование осей, знаков и единиц необходимо записать. Параметры X_speed/Z_speed из таблиц нельзя непосредственно подставлять как studs/second. Масштаб, масса персонажа, длительности и форма отбрасывания остаются UNKNOWN до измерения и приёмки адаптации. Новая геометрия должна быть самостоятельной, а не копией карты ROM.

## Реальные акторы и побочные эффекты

Создание персонажа должно быть связано с ReserveSpawn/CommitSpawn/AbortSpawn, уникальным actorId и подтверждением успешного появления. Невыполненный физический spawn не расходует жизнь. Повторный вызов или callback старого Humanoid не должен повторять повреждение, смерть, импульс, перенос или списание запаса. При disconnect/reconnect старые callbacks и connection epoch отбрасываются.

Политика владения физикой записывается и проверяется отдельно. Сетевое владение клиентом позволяет влиять на физическую симуляцию и Touched; обычная проверка RemoteEvent не делает позицию клиента доверенной [R2]. Серверное владение критическими объектами может потребовать компромисса по плавности [R3]. Данный пакет не включает скрытое включение нового режима Server Authority или изменение проектных настроек.

## Щиты и опасности

Защита 2 секунды и аварийная защита 10 секунд проверяются согласно принятым D-02.2/D-02.5, а не получают длительность из NES-счётчика 0x7F. Для аварийного щита нужны реальные испытания удержания над пропастью, прекращения при атаке, автоматического переноса после обнаружения безопасной опоры и повтора по таймауту только при доступном запасе. Воспроизведённый NES-фильтр не доказывает физическое поведение этих режимов Roblox.

Камера, непроходимая стенка, отсутствие опоры и смертельная поверхность имеют отдельные условия. Поиск безопасной точки подтверждает наличие опоры и места для всего персонажа, отсутствие смертельной поверхности и корректную принадлежность текущему уровню; одного попадания луча недостаточно как проектного критерия.

## Матрица фактической приёмки

| Блок | Необходимые запуски | Проверяемый результат | Статус |
|---|---|---|---|
| Привязка акторов | Сервер + 1/2/3 клиента | Фиксированный состав, свой actorId, корректные повторные появления | NOT RUN |
| Контакт/реакция | P1→P2, P2→P1; третья роль отдельно | Один принятый удар, единый профиль/переход, наблюдаемое смещение | NOT RUN |
| Границы | Безопасная опора; камера; стена; пропасть; опасная поверхность | Только соответствующая причина вызывает падение/смерть | NOT RUN |
| Щиты | Обычный и аварийный; атака; таймаут; появление безопасной точки | Принятые D-02.2/D-02.5 без второго расхода жизни | NOT RUN |
| Сеть | Задержка, jitter, потери; повторная/устаревшая команда; reconnect | Нет двойного урона/импульса/возврата; серверное состояние согласовано | NOT RUN |
| Устройства | Телефон/планшет, затем ПК и геймпад | Управление, видимость состояния и измеренная производительность | NOT RUN |

В Studio предусмотрены Server & Clients и средства сетевой симуляции [R4–R5]. Для каждого принятого запуска сохраняются commit, версия Studio/place, состав клиентов, устройство, фактический сетевой профиль, seed/сцена, исходные состояния, eventId, исход/отклонение сервером, позиции/скорости, HP/raw-состояние, shield, опора и остаток возрождений. Успешный Luau CI и `.rbxlx` сами по себе не являются таким запуском.
