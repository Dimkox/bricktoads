# CombatStand: запуск и фактическая приёмка

Это отдельный технический стенд, не замена `places/BrickToads.rbxlx`. Код не содержит ROM, исходного ASM, чужой карты или ресурсов оригинала. Сборка XML, успешные контракты Lua/Luau и компиляция не являются запуском Roblox. Начальный статус всех проверок ниже: **NOT RUN**.

## Получить сборку

Из корня репозитория выполнить `python tools/build_combat_stand.py`. Получится `build/CombatStand.rbxlx`. Флаг `--check` сверяет уже собранный файл с исходниками. GitHub workflow `Combat stand checks` также сохраняет place, SHA-256 и вывод контрактных тестов как артефакт своей конкретной ревизии.

Открыть этот файл в Roblox Studio. Сначала запустить Server & Clients с двумя клиентами. На первом подключённом клиенте нажать **Старт** после появления обоих. Состав фиксируется на момент старта: первые 1–3 подключённых пользователя. Поздний новый пользователь только наблюдает; возвращающийся прежний владелец получает свою роль в той же живой серверной сессии. Отдельный новый запуск после поражения выдаёт новый состав/ресурсы.

Управление: WASD либо сенсорная площадка слева; F / «Удар», R / «Таран», Space / «Прыжок». Камера следует Humanoid; серверные модели специально не назначаются Player.Character. Телефон/планшет нужно испытать отдельно: видимые touch-кнопки не доказывают проверенную мобильную пригодность. Движения/атаки пока без авторских анимаций; подсветка показывает попадание/защиту.

## Что является точным, а что экспериментом

Боевой raw Life хранится отдельно. Удар: 47→43→47 после лёгкой реакции. Таран: 47→31, 16→15, а при 15 выбирается смертельный профиль 21. Арифметическое получение нуля без underflow не означает смерть. Проверяется общая разрядная формула; полнота всех действий/состояний оригинала не заявляется.

Пять сердец показывают дробное `5 * rawLife / 47`. Это **предложение отображения для стенда**, не окончательно утверждённый перенос BT-33. Humanoid.Health служит только физическому телу и не хранит raw Life.

`Config.lua` явно содержит `EXPERIMENTAL_STAND_ONLY`: скорость/прыжок, размеры контакта, startup/window/cooldown, время реакции и задержка подтверждённой смерти — настройка стенда, не измеренные параметры оригинала. Импульсы задают добавку скорости в studs/s через `AssemblyMass`: профиль 18 — 9/0 по горизонтали/вертикали, 22 — 32/18, 21 — 34/27. Различие профилей сохранено, точная 3D-калибровка не принята. Полной анимации тарана и отдельного разбега атакующего нет: это ограниченный стенд контакта/реакции.

Обычный щит блокирует боевое повреждение на 2 секунды, но здесь не вводит иммунитет к смещению или смертельной геометрии. Аварийный щит держит тело до 10 секунд, снимается допустимой собственной атакой либо безопасным переносом; таймаут расходует ещё одно возрождение только при доступном запасе и подключённом владельце. Эти правила переноса — не доказательство исходного NES-счётчика защиты.

## Подготовка воспроизводимых сцен

Только в **серверной** Command Bar Studio доступен `game.ServerScriptService.CombatStand.Diagnostics`, BindableFunction. Клиенты не имеют такой команды; вне Studio объект не создаётся. Подготовка требует живых неподвижных героев без щита/реакции/начатой атаки. Номер P соответствует внутреннему слоту, не Roblox UserId.

Для обычного удара: `game.ServerScriptService.CombatStand.Diagnostics:Invoke("Case", "Safe", 1, 2)`, затем нажать F у P1. Для обратной роли подготовить ту же сцену со слотами 2,1.

Для края: `game.ServerScriptService.CombatStand.Diagnostics:Invoke("Case", "Edge", 1, 2)`. Цель стоит возле края основной площадки; нажать F у атакующего и записать реальный исход. Это сценарий проверки экспериментального масштаба, **не заранее гарантированный PASS**. Если падения не происходит или цель падает без удара, сохранить FAIL и калибровать сцену отдельно.

Для переходов тарана: `game.ServerScriptService.CombatStand.Diagnostics:Invoke("Case", "Dash16", 1, 2)` либо `"Dash15"`, затем R. Подготовка `"Safe"` + R проверяет начальный Life=47. После реакций можно повторять подготовку. Весь доверенный ввод диагностики помечается в серверном журнале.

Для аварийного появления: `game.ServerScriptService.CombatStand.Diagnostics:Invoke("NoSafe", true)` отключает столкновения разрешённых опор. После падения должен появиться удерживаемый герой. `...:Invoke("NoSafe", false)` возвращает опоры и позволяет проверить перенос без дополнительной жизни/лечения/двухсекундного щита. Оставить NoSafe включённым для циклов 3→2→1→0; отдельно атаковать под аварийным щитом. Ноль сам по себе не должен убивать живого героя.

`...:Invoke("Reset")` возвращает стенд в лобби; это только диагностический сброс, не игровой respawn. `print(game.ServerScriptService.CombatStand.Diagnostics:Invoke("Dump"))` выводит JSON состояния и последних 256 событий. Сохранять полный Server Output заранее: старые записи вытесняются из кольцевого буфера.

## Матрица приёмки

| Сценарий | Ожидаемая проверка | Фактический статус |
|---|---|---|
| Сервер + 1/2/3 клиента | Фиксированный состав, собственные тела/ресурсы | NOT RUN |
| Все направленные пары героев | Серверный контакт и единственный импульс, 18/22/21 | NOT RUN |
| Стена, камера, пропасть, опасная поверхность | Причины различаются; камера не убивает | NOT RUN |
| Обычный/аварийный щит, атака, безопасный перенос, таймаут | Сроки, отсутствие лишнего лечения/расхода | NOT RUN |
| Отключение и возврат в тот же живой сервер | Тело получает урон; владелец возвращается без лечения | NOT RUN |
| Задержка, jitter, потери, повтор/устаревшая команда | Нет второго попадания/импульса/персонажа | NOT RUN |
| Телефон/планшет | Touch, HUD, камера, измеренная производительность | NOT RUN |

Для каждого запуска записать commit, SHA-256 place, версию Studio, 1/2/3 клиентов, устройство/ОС, сетевой профиль, подготовку, действие, ожидаемое и наблюдаемое состояние, Server/Client Output и PASS/FAIL/NOT RUN. Закрытие последнего клиента и исчезновение сервера не тестируют возврат в прежнюю живую сессию. Реальный reconnect с тем же аккаунтом и маршрутизацией в живой сервер требует отдельного испытания; сам счётчик connectionEpoch этого не доказывает.

## Граница использования

Не переносить диагностический стенд в публичный продукт без ревью/приёмки. Серверное владение телами выбрано для контроля исходов, но плавность/задержка не измерены. Проверка типов Roblox API, независимое внешнее ревью, реальные игровые испытания, весь первый уровень, NPC, босс, захваты/оружие и человеческие враги этим результатом не закрываются.

Официальные справки: Roblox Creator Hub — `scripting/security/client-server-boundary`, `physics/network-ownership`, `studio/testing-modes`, `studio/network-simulator`. Они не заменяют журнал этой сборки.
