# Shadow Cloud — ТЗ на зелёную облачную голову

Версия 1.0, 9 ноября 2026. Исполнители: 3D художник, аниматор, интегратор Roblox.

## Результат и граница имени

Создать отдельную модель каталожного образа [enemies-03, строка 3, столбец 3](../../../assets/concept-art/uhd-cast-2026-11-09/enemies-03-uhd.png): плотная неровная зелёная облачная голова с большой тёмной пастью справа внизу. Общие требования: [стандарт моделей](../MODEL_STANDARDS_RU.md). Это видимый объёмный персонаж, а не одна дымовая частица или плоский billboard. Голова без торса, конечностей, оружия, глаз на стеблях и инопланетного шлема.

Название Shadow Cloud на утверждённой доске является именем визуального ассета. Его исходная маска28×22 почти полностью совпадает с object gfx `0xBD` pinned source: при сравнении восстановленного контура отличается один пиксель. Соседний [Swellcheek](swellcheek.md) точно совпадает с кадромBC. Обработчики `5D/5E` и `62` используют оба кадра, следовательно, две подписи доски не устанавливают две независимые NES species/FSM. Нужны два узнаваемых каталожных образа и согласованная переходная геометрия; тип игрового появления подтверждается отдельно.

## Формообразование и риг

Рабочий масштаб Roblox: ширина5,2 studs, высота4,2, глубина3,6. Это предложенный 3D масштаб, не исходное измерение. Ноль в центре объёма, +Y вверх, -Z из пасти, L=X<0. Сохранить крупные округлые доли, тёмно-зелёные тени, яркие жёлто-зелёные грани и чёрную глубокую полость. Поверхность бугристая, но не лиственная: не приклеивать настоящие листья. Задняя сторона продолжает облачный объём, а не зеркалит фронт с ещё одной пастью.

Сборка `Root > Core`, 4–6 крупных `Lobe` узлов, `MouthUpper`, `MouthLower`, `MouthRim`; максимум12 bones/Motor6D. Доли допускают малый пульс и сжатие. Край пасти остаётся непрерывным в открытой/сжатой позах; внутри нужно закрытое горло. Большие выпуклости моделировать, мелкую зернистость запекать. Подготовить совместимую форму перехода BC↔BD с сохранением root и основных долей; если нужны два mesh-варианта, их замена не меняет actorId, положение и столкновения.

Сокеты `Aim`, `Mouth`, `GasOrigin`, `WindOrigin`, `HitFX` принадлежат Core/пасти; наружное направление локальной -Z. Положение выпуска перед существующей пастью является авторским 3D решением. Тёмная полость не служит порталом, местом проглатывания героя или отдельной уязвимостью. Неиспользуемый режим не оставляет работающие эмиттеры.

## Механики, которые должен поддержать комплект

У `object_swellcheeks 0x62` есть режим создания газа: `main.asm`14024–14204 содержит переход `JMP loc_0_F051`, общий участок19181–19202 создаёт объект `0x53`. Сам газ имеет отдельный конечный обработчик `object_gas`, в Revolution выбирающий кадрC5. Это важное разделение: большая зелёная головаBD не становится самим газовым снарядом только по слову Cloud. Подготовить отдельный небольшой prop/effect `GasCloud`, не копировать всю голову как projectile.

КадрBD также используется ветровыми `object_last_lvl_flying 5D/5E`; их `sub_0_F10E` создаёт ветер. Поэтому ветровой цикл нужен как совместимое представление, если конкретная расстановка подтвердит этот путь. Текущий [контроллер](../../../src/server/gameplay/CampaignEnemies.lua) содержит `Swellcheeks=Fly/Gas` и отдельно `FlyingHead`; эти runtime имена не заменяют source проверку. `FlyingHead` нельзя автоматически назначать облакуBD по слову «голова».

Сдать `HoverIdle`, `Drift`, `Turn`, `MouthPulse`, `GasTell`, `GasRelease`, `GasRecover`, `WindTell`, `WindBlow`, `WindStop`, `HitLight`, `HitHeavy`, `Defeat`, `TransitionBC/BD`. Газовый цикл сжимает объём, собирает массу у пасти, выпускает один подтверждённый конечный эффект и возвращается к исходному силуэту. Ветровой цикл удерживает направление и пульсирует, но сам не задаёт damage. Маркеры `GasRelease`, `BlowOn/Off`, `RecoveryEnd` — только события изображения. Длительности, траектории и мимика являются авторской адаптацией.

## Физика, лимиты и поставка

Не использовать цепь физических шаров для долей. Декоративные mesh не сталкиваются с героями; стартовый hurtbox головы примерно3,8×3,6×3 studs уточняется по принятому адаптеру. Размер пасти и пульс не расширяют серверную атаку. У газового эффекта отдельная серверная swept геометрия, конечный срок и отсутствие playable slot. Он может продолжить разрешённый полёт после смерти стрелка; смерть визуальной головы не удаляет принятый эффект произвольно.

Loader Life47/79/111 относится к конфигурациям обычного62. Не назначать эти числа каждому объекту с графикойBD, не создавать босса с фазами и не выдавать HP самому газу/ветру. Сервер хранит Life, ownership, реакцию и одноразовую жизнь; смена роли не создаёт второе облако. Поражение выключает локальные циклы и оставляет конечное рассеивание без продолжающейся атаки.

LOD0 до10 000 треугольников, LOD1 до5 000, LOD2 до1 800; каждый mesh до8 000. До двух материалов, Color/Normal1024², Roughness/Metalness512². Для `GasCloud` до800 треугольников либо ограниченные частицы. Дальние LOD сохраняют открытую пасть и основной неровный силуэт; никаких многослойных прозрачных сфер с высоким overdraw.

Сдать исходник, FBX/GLB, Roblox Model, LOD, текстуры, клипы, отдельный газовый эффект и манифест `visualName/sourceGfx/sourceType/runtimeKind`. Приёмка включает оборот360°, непрерывный край пасти, совместимость BC/BD, разные циклы Wind/Gas и конечное рассеивание. Обязательный пункт интеграции — записать source type для каждой расстановки; отсутствие такого соответствия не разрешает придумывать новый бой по подписи листа.
